## P2：关闭跟随客户语言后仍扫描消息并调用已被拒绝的协议

- 位置：`runtime/page/index.ts:20-23`，以及会话/可见性变化调度 `:28-31`。
- 复现：以生产状态 `followCustomer={lang:null,following:false,manualEnabled:false}` 调用 `mountPageFeatures`；页面包含一条 `.chat_list_content li.normal-message-item.customer .chat-content .chat-text`。首次等待 450ms，再修改客户消息并等待 450ms。
- 独立证据：通过内存 esbuild bundle + JSDOM 执行上述流程，未连接真实客户端；bridge 记录到两次 `setTarget([{lang:"en",source:"auto",conversationKey:"fixture-chat"}])`。`electron/embedded-host.ts` 和 `runtime/driver.ts` 均只允许 `source:"manual"`，因此真实运行中两次都会被拒绝，catch 又清空 `lastAuto`，后续消息仍重复发起。
- 影响：生产桥已经明确关闭自动跟随，但页面仍观察整个 body 的消息变更、遍历客户消息并发无效 CDP 请求；形成协议不一致、无用日志及没有业务收益的工作。未测得真实 CPU/p95，不能把它扩大描述为已发生性能事故。
- 建议：从当前生产页面移除自动语言 observer/扫描，或仅在明确启用且协议支持时安装与调度；保持现有窄桥拒绝自动目标的边界。补充测试：跟随关闭时客户消息、切会话和 visibility 恢复均不应发自动目标请求。

## 审查中发现并已复核的修复

租约超时曾使已失效的 `external` 引用保留：后台 renew 吞错、observe 只清空草稿，而自动重连要求 `!external`。系统挂起超过租约后可能无法自动恢复。当前 `CompanionService.retireComposer`、renew catch 与 observe 对不可恢复租约错误的处理已经覆盖此路径。

独立复核：内存 esbuild 加载当前服务，将 external.read/renew 设置为抛出 `NATIVE_LEASE_ENDED`，运行 1750ms，结果为 `reads:1,reconnects:1,retainsDeadExternal:false,composerSource:"unavailable"`。这里只证明服务会清除死连接并进入重连；未证明睡眠恢复后的真实 renderer 行为与重新挂载成功。

## 已核对的边界

| 项目 | 本轮证据与结论 |
|---|---|
| 禁止发送 | 生产入口 `electron/main.ts` 使用内嵌业务服务；桥只允许固定 action/参数形状。`apply` 仅接受 `mode:"replace"`。native adapter 仅有读取、租约、交互通知与草稿 CAS；未发现可达的发送按钮 click 或 Enter 注入。 |
| renderer 窄桥 | CDP binding 按 session、executionContext、随机 binding 名检查；参数不接受任意脚本文本、URL、凭据、草稿 snapshot 或替换文本。状态投影不包含 token、浏览器 profile 或认证账号凭据。 |
| 草稿竞态 | 翻译回包后重读草稿；替换前重新认证、检查 target/message nav、运行同步最终授权，再由 native adapter 同步检查完整 snapshot、纯文本、IME、焦点和会话。写后检查公开 update 事件和内容。 |
| 订单竞态 | 每次显式查询递增 orderGeneration，取消旧请求；前后重读草稿上下文，账号/会话/target 变化清空订单状态。投影白名单标量字段，页面用 textContent 渲染。 |
| 订单 perform | 已独立读取本地服务合同副本 `work/tsim-host-integration/central-backend/api/routers/agent_package_query.py:1104-1129`：受 `complaint_records` 权限保护，POST 转发 `/v1/customer_service_panel/query`。它是查询入口，允许产生查询记录；没有因此引入退款、取消或发送。后续只有 dataplan-list/detail GET。本地副本不能证明当前远端部署合同一致。 |
| 多 target | 依据固定隔离 world 的 visibility/focus 观察选择唯一 target；多候选无法确认时拒绝，不按枚举顺序取首项；读取/替换前重新核对，变更时使旧 driver 失效。真实 Electron BrowserView 的 visibility/focus 是否足够区分账号尚未实测。 |
| 清理 | 页面 UI/native 均有六秒租约、显式 detach/dispose；移除自有 host、observer、事件与 binding；transport 故障会使 driver 失效。原客户端调试端口随客户端继续存在，不等同助手退出即关闭端口。 |
| 构建 | 常规 build-electron 将 native/runtime browser bundle 内联进 main.cjs 并固定 hash，打包 files 只列 dist、main/preload、package.json；不依赖 work 产物。仅由配置不能证明最终 portable 内容、冷启动、卸载或回退可用。 |
