# Windows 官方客户端资源注入方案与构建说明（2026-10-16）

本文根据 2026-10-16（Asia/Singapore）的项目对话与当前源码整理，覆盖 Windows 构建、功能变化、登录机制、验收、故障定位和清理。Windows 包尚未在本轮实际构建、安装或完成业务验收；下面的“已实现”表示源码与回归覆盖，不等于 Windows 实机通过。

**Windows 的目标交付方式与 Mac 统一：一个安装 EXE 完成一次资源注入，日常只打开官方客户端。** 安装器修改官方客户端的 `resources/app.asar`，加入助手启动接入代码，将助手放在客户端安装目录中；以后由官方程序启动链路带起助手，退出时停止助手。Windows 并不存在必须采用外部托盘助手、不能修改 Electron 资源的限制。

Mac 当前已采用直接注入官方 `/Applications/旅游商家桌面版.app`（`npm run inject:mac -- --install`）：修改 `Contents/Resources/app.asar` 中的入口，增加 bootstrap，嵌入助手并配合启动器工作。当天的 ARM 集成 ZIP、PKG、修复 PKG 属于历史路线。

**实现状态：Mac 资源注入已有实现；Windows 的同类安装 EXE、资源接入和卸载恢复尚待实现与实机验证。** 仓库现有 Windows 轻量宿主和 Electron 便携包是可供复用、调试和回退的外部运行方案，不是最终的一次安装注入包。本文第 1、14.2 节描述目标方案，第 2–7 节保留现有宿主构建方法，不能将这些命令的产物当成已经完成的资源注入安装器。

本版包含的出站翻译改动：

- **Enter 直接发送译文（默认）**：在回复框按 Enter，助手先把草稿替换成译文，读回核对后再点击客户端的发送按钮。译文还没出来时，立即发起翻译，等译文返回后自动替换并发送；等待期间状态栏显示「译文生成后自动发送」。
- **替换模式**：在面板「⋯」菜单的「Enter 键行为」里切换。替换模式下 Enter 交给客户端照常发送原文，译文需点「替换草稿」或按 `Ctrl+Alt+Enter` 写入。
- **自动翻译等待**：停止输入 500 毫秒后发起翻译（原为 1500 毫秒）。

两种 Windows 包（轻量宿主和 Electron 回退包）复用 `electron/companion-service.ts` 和 `runtime/native-composer.ts`，都包含上述发送与翻译逻辑；登录来源和宿主生命周期有差异，详见第 9 节。

## 1. 统一采用官方 Electron 资源注入

### 1.1 安装与日常运行

目标流程如下，均为 Windows 待实现的验收要求：

1. 用户双击一个安装 EXE，安装器定位官方客户端，核对版本、可执行文件、`resources/app.asar` 及相关页面资源指纹；需要写入受保护目录时申请管理员权限。
2. 确认客户端及旧助手已退出，备份原始 ASAR、入口信息和本次需要改动的其他文件，写入安装收据；在暂存位置生成并校验完整新资源。
3. 在 ASAR 内添加 Windows 启动接入代码，保存原始 `package.json.main` 并将入口指向 bootstrap；bootstrap 接入助手启动与退出管理后继续加载官方原入口。助手程序和资源安装在客户端目录的自有子目录中，不能依赖开发目录。
4. 通过可恢复事务替换资源并复验。安装后用户直接打开原官方 EXE 或原快捷方式，无需先打开助手、点击托盘或再次运行安装器。
5. 官方程序启动时自动启动且只启动一个匹配实例的助手；官方程序退出时停止对应助手，自身重启时正确交接。翻译、订单增强仍依赖运行中的助手进程，不是安装后就不需要运行时代码。
6. 卸载时核对当前文件与安装收据，恢复原资源并移除自有文件；官方升级覆盖资源后，重新核对新版本兼容性再接入，不能把旧备份盲目覆盖到新版。

### 1.2 修改资源与页面注入的关系

“安装时修改 `app.asar`”和“运行时把面板注入客服页面”是两个阶段，可以同时存在。前者让官方启动链路自动接入助手，后者提供翻译与订单界面。无需为了统一安装形式而重写已有的翻译、草稿校验和面板模块。

Windows 计划复用现有页面运行时 `runtime/runtime-ui.tsx`、面板 `runtime/page/outbound-panel.ts` 和服务逻辑。若继续使用现有本机调试连接，启动接入代码必须在 Electron 初始化的正确阶段启用仅监听 `127.0.0.1` 的连接，再由助手核验目标后接入；仅在已经启动完成的进程中添加参数不能作为可行性证明。端口分配、进程身份与重启交接必须在 Windows 实测。

Mac 的 ASAR 修改已在 `scripts/lib/mac-pkg-asar.mjs` 中实现：保留原业务文件字节，追加 bootstrap 与原入口记录，并更新归档入口。Windows 可以沿用这一设计，但必须核对自己的 ASAR 布局、Electron 版本和完整性检查。不能直接复制 Mac 的路径、启动器或签名处理，也不能把历史 `scripts/patch-client.mjs` 静态 HTML 补丁当成目标安装器。

### 1.3 两端差异与当前可用构建

| 项目 | Mac 当前实现 | Windows 目标 |
| --- | --- | --- |
| 修改位置 | App 包内 `Contents/Resources/app.asar` | 官方安装目录 `resources/app.asar`，以实际客户端结构为准 |
| 接入方式 | bootstrap、嵌入助手及启动器协作 | Windows bootstrap 与随客户端运行的助手；确保原 EXE/快捷方式直接生效 |
| 权限与签名 | App 权限、重新签名及校验 | 安装目录权限、文件占用、可执行文件签名和 ASAR 完整性兼容性核对 |
| 生命周期 | 已有厂商进程身份与重启交接实现 | 移植并验证 Windows 进程身份、单实例、退出和重启交接 |
| 交付状态 | 已有直接注入脚本，仍有本文所列实机限制 | 单 EXE 安装、资源注入、更新与卸载流程待实现 |

以下是**现有外部宿主构建**，可作为安装器载荷的候选或开发回退，不代表安装器已经完成；最终选用哪种宿主还需结合第 9 节的登录能力确定：

| 包 | 当前入口 | 当前用途 |
| --- | --- | --- |
| 0.4.0 轻量宿主 | `npm run package:lightweight` | Node.js 24 + C#/.NET 原生托盘，现有调试/运行方案 |
| 0.3.2 Electron 便携包 | `npm run package:win` | Electron 宿主，现有调试/回退方案 |

当前这两种包不修改厂商安装资源，需要单独启动；它们复用同一份页面运行时，不能同时运行。**`npm run package:win` 生成的便携 EXE 不是目标资源注入安装 EXE。当前没有可直接执行的 Windows 资源注入安装器构建命令。**

## 2. 现有宿主的构建环境

- Windows 10/11 x64
- **Node.js 24.x**：打包脚本会把正在运行的 `node.exe` 复制进发布包；不是 24.x 会报 `NODE_24_REQUIRED` 并停止
- **.NET 10 SDK**：用于编译 `native/resident`（轻量宿主）和 `native/windows`（Electron 回退包）；发布产物是 self-contained，用户机器不需要另装 .NET
- PowerShell 5.1 及以上，Git

检查版本：

```powershell
node -v
dotnet --list-sdks
```

## 3. 同步代码

先确认 Windows 工作区已同步本次完整源码（包含新增文件），再构建。可以先在 Mac 提交并推送后，在 Windows 上 `git pull`；也可以完整复制源码，排除 `node_modules`、`work`、`dist*`、`release` 和各平台 `bin` / `obj`。不要复用 Mac 的依赖目录，在 Windows 执行 `npm ci`。本文不代表代码已经提交或推送。

与出站翻译相关的主要文件，可用来核对是否同步完整：

- `runtime/native-composer.ts`：拦截回复框里的普通 Enter；`sendDraft` 只在草稿和刚读回的内容完全一致时点击发送按钮
- `electron/companion-service.ts`：等待译文、替换后发送；常量 `AUTO_TRANSLATE_DELAY_MS=500`
- `runtime/page/outbound-panel.ts`：面板及「⋯」菜单里的模式开关
- `runtime/driver.ts`、`runtime/cdp-policy.ts`、`electron/external-composer.ts`、`electron/embedded-host.ts`：发送调用和模式切换的接线
- `src/shared/workbench.ts`、`src/shared/companion-api.ts`：`OutboundMode` 类型
- `scripts/build-electron.mjs`、`scripts/build-lightweight-node.mjs`：产物清单 `customerSend` 改为 `"user-enter"`

同步后可在 Windows 上确认：

```powershell
Select-String -Path runtime\native-composer.ts -Pattern 'sendDraft' -SimpleMatch
Select-String -Path electron\companion-service.ts -Pattern 'AUTO_TRANSLATE_DELAY_MS=500' -SimpleMatch
```

`prototypes/panel-redesign/` 里是设计原型和本地预览页，不参与构建，可以不复制。

## 6. 现有外部宿主的本机验收

以下托盘启动步骤仅用于当前外部宿主。最终安装注入版须先执行第 14.2 节安装验收，日常直接启动官方客户端，再复用本节面板与业务检查。

1. 退出旧版助手，再双击 `TravelMerchant.Resident.exe`。
2. 用托盘的「启动客户端」，或者按 README 中「使用」一节，让原客户端带本机调试连接启动。
3. 打开消息页，回复框上方应出现新面板，并逐项检查：

| 检查项 | 预期 |
| --- | --- |
| 顶栏 | 开关、「中文 → 日语 · 自动」语言标签、状态点、放大镜、订单号、「⋯」 |
| 语言标签 | 点开弹层（不应被裁切或跑到屏幕外）；能搜索语言、选择手动语言、切回「跟随客户语言」 |
| 订单号 | 点击后**直接**打开 TSim 订单窗口，没有二级弹层；Esc 能关闭 |
| 放大镜 | 弹出「查询其他订单」；先选中页面上的订单号再点，号码会自动填入；非法字符会提示错误 |
| 翻译 | 输入中文，停顿约 0.5 秒后出现译文 |
| Enter 直接发送（默认） | 译文就绪时按 Enter：回复框先变成译文再发出，客人收到的是译文；输入后立刻按 Enter：状态栏显示「译文生成后自动发送」，译文返回后自动发出 |
| Enter 等待中继续输入 | 按 Enter 后、译文返回前继续打字：取消这次发送，不会发出旧内容 |
| 中文输入法 | 组词时按 Enter 只上屏，不触发发送；`Shift+Enter` 仍为换行 |
| 无需翻译时 | 暂停翻译、关闭出站翻译或客户语言尚未识别时，Enter 由客户端照常发送原文 |
| 替换模式 | 「⋯」菜单 →「Enter 键行为」→「替换模式」：Enter 不再被拦截；「替换草稿」和 `Ctrl+Alt+Enter` 只替换草稿，不会发送 |
| 状态 | 需登录时卡片内显示「登录 TSim」按钮；暂停后显示「恢复翻译」；中文客户显示「无需翻译」 |
| 窄窗口 | 把客户端窗口缩窄，顶栏只剩图标，不换行、不溢出 |
| 高 DPI | 125% / 150% 缩放下，弹层与按钮的位置正确 |

4. **验收 Enter 发送时请用测试会话**：该功能会真实发送消息给对方。
5. 日志位于 `%LOCALAPPDATA%\TravelMerchantResident\logs\`。

## 7. 现有外部宿主回退

先从托盘退出 0.4.0，再启动保存好的 `TravelMerchantCompanion-0.3.2-win-x64.exe`。两种宿主不要同时运行，否则会争用同一页面的挂载租约。资源注入版的卸载回退必须恢复安装收据对应的官方资源，不能只通过切换外部宿主 EXE 代替。

## 8. 已知风险

- Enter 直发依赖客户端发送按钮的选择器 `.chat_area-button .list-btn_send button.btn_send`（全页必须唯一且可见、未禁用）。找不到唯一可用的按钮时不会发送，会提示「未能自动发送」，此时译文已写入回复框，可手动发送。客户端改版后需要重新核对这个选择器。
- 模式选择目前不保存，每次重启助手都回到默认的「Enter 直接发送」。不要以旧包 README 的“只替换不发送”判断新版本 Enter 行为。
- 翻译失败时不会发送原文，需要再按一次 Enter 重试，或切换到替换模式。

- 面板的弹层采用 fixed 定位，避免被客户端 `overflow:hidden` 的容器裁掉。如果客户端某个上层元素带 `transform` / `filter`，弹层位置可能偏移。这一项在 Windows 上需要重点看。
- 已经过时、不要使用：`scripts/patch-client.mjs`（静态文件补丁）属于历史实验，不在默认构建中；固定支持旧版客户端，会修改客户端文件。

## 9. 登录态、持久化与两种宿主的区别

本节描述现有宿主能力。修改官方 ASAR 只是安装与启动接入方式，不会自动改变登录来源；资源注入版必须明确采用哪种宿主并随包验证其认证链路。

订单查询页面和翻译服务的登录链路相互独立。订单 iframe 能弹出或已登录，不代表翻译已获得 TSim 身份；旅游商家账户也不是 TSim 账户。

| 项目 | 0.4.0 轻量宿主 | 0.3.2 Electron 宿主 |
| --- | --- | --- |
| 入口 | `host-node/main.ts` | `electron/main.ts` |
| 翻译身份 | 默认 `BrowserProfileSessionService`，读取可验证的 Edge/Chrome TSim 会话 | 显式接入 `PersistentSessionService`，助手自己的 TSim 登录与加密会话 |
| 登录入口 | 打开 `https://csagent.tsim.tech/login`，随后重新同步浏览器配置 | 打开受限的本机登录页，通过允许的 TSim API 登录 |
| 跨重启恢复 | 依赖浏览器配置中的有效登录态及读取权限 | `userData/auth/tsim-session.enc`，启动解密后向服务端核验 |
| 加密存储 | 尚未接入 Electron 的 `safeStorage` 持久会话实现 | 使用 Electron `safeStorage`；不可用时明确失败，不降级明文 |

因此，不能承诺轻量宿主已拥有 Electron 版的独立持久登录。若 Windows 的主要验收目标是该登录机制，应分别测试两包，明确选择的包。浏览器自动发现失败应区分“确实未登录”“权限或解密受限”“配置不匹配”“网络失败”，避免一概提示重新登录。

Electron 持久登录的已实现规则：

- 只保存 `accessToken` 与 `sessionRef`，不保存用户名密码；凭据留在宿主，不发送给注入的厂商页面。
- 文件加密、受限权限、串行读写、临时文件写完再原子替换；拒绝异常大小、无效结构和不安全的存储后端。Windows 的文件权限效果仍需实机检查。
- 启动先恢复并请求 `/agent/profile` 验证账户及权限；后台默认每 60 秒同步。JWT 临近到期 5 分钟内刷新；无法解析到期时间的令牌按 30 分钟刷新间隔处理。服务端决定最终有效期，不能承诺永久登录。
- 服务端拒绝身份（如 401/423）或明确注销时撤销身份、取消旧请求并清除保存的会话；网络故障不应当成“用户主动注销”。
- 登录恢复后重新调度草稿翻译，修复认证恢复过程中首个翻译被取消、客户目标语言被清空的问题。
- 页面仅在确认需要登录时显示临时登录按钮；连接中和读取失败有独立状态，避免常驻一整行登录提示。
- 加密会话文件损坏时提示重新登录，允许登录流程清理并重建；存储读取权限、网络或加密后端问题仍显示失败，不误要求用户反复登录。
- 持久登录页去掉容易误解的“退出此辅助会话”按钮。登录成功后直接关闭标签页即可；真正的注销仍会使本地保存的身份失效。

当天 macOS 旧浏览器读取曾被系统隐私权限拒绝；这不能证明 Windows 有同样原因，也不能用“再登录一次”代替权限排查。真实接口与官方编辑器资源曾完成两次 HTTP 200 翻译、按钮和快捷键替换读回，但那是组件复测，未覆盖 Windows 安装、冷启动恢复或所有浏览器配置。

## 10. 长文本、引用和会话语言修复

### 10.1 长文本滚动与格式

此前几十行文本在滚到末尾时，编辑器顶部移出回复区，几何校验将其误判为不可用。现在按视口与祖先滚动容器裁剪后的可见交集判断；还考虑厂商 `height:0` 配合可见溢出的布局，文字仍可见时不会只因边框区域移出视野而禁用翻译。覆盖顶部、中间、底部三种位置。

正文读取支持纯文字的常见 Tiptap 结构：段落、标题、代码块、引用块、列表、硬换行，以及粗体、斜体、删除线、行内代码标记。仍拒绝不认识的节点或标记，不把图片等内容盲目转换后写回。译文写入以纯文本段落重建，不承诺保留正文的原格式。

这不是无限长文本支持：当前正文及替换文本上限为 **20,000 个 JavaScript 字符单位**，文档最多 1,000 个顶层块、5,000 个节点、嵌套深度 32；API 响应另有长度与回显验证。超过限制应提示并由用户拆分，不能强行放宽验证。

引用客户消息与编辑器正文分开处理。引用增加、删除或变化会更新草稿版本，重新触发翻译；替换正文前后核对引用指纹，避免误删引用。即使引用变化后正文恢复原样，也会撤销旧的“已尝试”状态，允许再次翻译。

### 10.2 客户语言与会话隔离

- 从可见客户消息采样，排除商家消息；同轮扫描缓存祖先样式读取，下一轮重新计算，避免用永久缓存遗漏显隐变化。
- 语言扫描采用 300 ms 的有界调度，连续输入、滚动或 DOM 更新不会一直推迟识别。语言上报失败按 1 秒间隔有界重试，最多 4 次，并检查当前会话和状态回显。
- 同一客户编辑器暂时不可读、滚动或重建时，保留已有客户语言；一次 `unknown` 观察不会覆盖已知语言。此保护不跨客户会话复用。
- 会话身份来自唯一、可信的订单详情 iframe，包括 `groupid`、`sessionid` 等字段，并组合目标实例、文档代次、账户和编辑器作用域。来源不唯一或不可信时不授权替换与发送。
- 切换客户、目标客户端或账户后立即撤销旧语言、预览、订单结果、翻译请求和待发送意图。异步返回必须仍匹配当前上下文；页面先切、宿主状态后到时也会先隐藏旧译文。
- 手动选择语言与“跟随客户”可切换；中文客户、未知客户语言、暂停或关闭翻译时按实际状态处理，不能为了触发翻译而猜测客户语言。

### 10.3 Enter 的安全边界

默认“Enter 直接发送”只响应用户在官方回复框中的可信普通 Enter。输入法组词、`Shift+Enter`、其他修饰键不触发自动发送；替换快捷键仅替换。翻译失败不会回退发送原文。

替换与发送均执行当前草稿的比较交换：核对会话、草稿版本、文档、编辑器、账户、焦点及可见性；替换后再次读回，与译文完全一致才调用唯一且可用的发送按钮。等待译文期间继续输入、切换客户或登录身份变化均会取消旧发送。发送按钮失效时保留已写入草稿并提示人工核对。

## 11. 面板、订单窗口与界面优化

当前面板采用紧凑单行顶栏，语言列表收纳到可搜索弹层；翻译开关、语言状态、订单快捷入口和更多菜单集中显示。低高度窗口限制译文区域并允许滚动，窄聊天窗压缩标签；历史对话中的“两列按钮”和完整常驻语言列表是较早设计，不能当作当前截图基准。

替换按钮只显示当前系统的快捷键：Windows 为 `Ctrl+Alt+Enter`，macOS 为 `⌘+⌥+Enter`。提示位于操作按钮，不再占用独立说明行。

订单号芯片直接打开 TSim 订单窗口；放大镜用于查询其他订单，可读取当前选中文字作为初值并校验字符。订单窗口随客户会话切换关闭，避免把上一客户结果留在当前客户界面；Esc 关闭。窗口可打开不等于订单查询业务或权限已验收。

Electron 设置窗口已改为显式打开，启动、激活、重复启动不会自动弹出；关闭窗口后不自动重现。macOS 还隐藏助手 Dock 与菜单栏图标；这是平台分支行为，Windows 仍保留原生托盘入口，不能照搬为 Windows 无托盘承诺。

## 12. 启动速度、注入兼容性与白屏状态

### 12.1 已实现的开销优化

| 优化 | 作用与边界 | 主要源码 |
| --- | --- | --- |
| 面板不等待远端认证 | 先挂载本机可信 UI，认证异步恢复；登录慢时仍可显示连接状态 | `electron/companion-service.ts` |
| 减少启动重复等待 | 缩短无效旧窗口发现等待，等待编辑器准备好后再接入 | `electron/external-composer.ts`、`runtime/driver.ts` |
| 文件指纹复用 | 元数据完全一致才复用哈希；合并并发读取，文件变化即失效，仍核验真实指纹 | `runtime/fingerprint-cache.ts`、`runtime/file-fingerprint.ts` |
| 相同状态去重 | 减少空闲时每半秒重复状态通信、页面重绘；保留心跳与操作时校验 | `electron/main.ts`、`host-node/main.ts`、`runtime/driver.ts` |
| 减少消息观察器重绘 | 消息列表变化只在会话绑定变化时重绘面板；新宿主状态照常渲染 | `runtime/page/index.ts` |
| 语言扫描内样式复用 | 减少同一轮对共同祖先的重复样式读取 | `runtime/page/language.ts` |
| 受限前台加载窗口 | 仅给可信本机 IM 页面临时取消后台节流，完成加载后恢复，最长 30 秒 | `scripts/lib/macos-vendor-bootstrap.cjs`，仅 macOS 注入 |

macOS 早期正常重启实测，运行时就绪约由 29 秒降至 24–27 秒，聊天页出现后的注入等待约由 18 秒降至 12–14 秒。该结果属于当时的 macOS 构建，不能推算 Windows 或本次最新构建的耗时。后续性能改动多为代码和回归验证，未重新测量真实提升。

### 12.2 热更新与指纹

当天 macOS 客户端热更新到 `ares 1.2.16` 后页面路径发生变化，旧路径导致面板无法注入；现已增加从已校验的热更新页面生成构建信息的流程，历史实测确认面板恢复。macOS 注入时生成的可执行文件、归档和页面哈希必须一致更新，不能只复制一个 JS。

Windows 当前固定清单仍在 `runtime/build-manifest.ts`：客户端 `1.2.11.2664320`、package `1.2.11`、ares `1.2.14`，默认安装路径 `C:\Program Files\vbk-electron\旅游商家桌面版.exe`。macOS 的 `1.2.12` / ares `1.2.16` 支持不代表 Windows 版本自动受支持。Windows 客户端或路径不匹配时，需要重新取证并建立兼容清单，禁止仅改版本号、跳过 SHA-256 或放宽来源校验。

### 12.3 首次消息页白屏仍未验收通过

**这是尚未解决的已知问题，不能写成“已修好”。** 当天最后一轮 macOS 实测中，IM DOM 已存在且尺寸正常，原生窗口仍白屏；切换标签或手动重新挂载视图可恢复。源码已加入主窗口与 IM 都完成加载后、保持选中标签和尺寸的受限重新挂载，并覆盖加载顺序、重载、销毁及用户切走等场景，但后续真实首启依然出现白屏，对话在继续诊断时中断。

因此，单元测试、DOM ready、面板存在、签名和指纹一致，都不足以判定首开白屏消失。后续需要以 ego-browser 发起正常冷启动，不点击或切换标签，同时核对原生窗口实际画面与 IM 页面状态，确认消息区可见；Windows 也需独立执行这一验收。不要把 macOS `BrowserView` 校正直接声称为 Windows 已完成的修复。

## 13. Windows 详细验收与排障

除第 6 节外，发给同事前至少补齐以下实机记录，记录系统、DPI、客户端版本、构建提交及所用包。现有外部宿主分别验收；未来资源注入版还必须通过第 14.2 节的安装与生命周期验收。

| 场景 | 必须确认 |
| --- | --- |
| 冷启动默认消息标签 | 不切换标签即可显示 IM；面板最终出现；分别记录客户端、IM、面板、认证就绪耗时 |
| 登录恢复 | 首次登录后关闭标签、退出并重开助手、重开客户端，翻译仍能恢复；明确测试的是浏览器会话还是加密会话 |
| 认证异常 | 断网显示失败而非错误地注销；身份失效显示临时登录按钮；成功登录后原草稿重新翻译 |
| 长文本 | 几十行草稿在顶部、中部、底部均可读、可翻译、可替换；保留换行，无需滚回顶部 |
| 格式与引用 | 粗体/列表等受支持文字可翻译；添加、删除引用能重新触发，替换后引用仍在 |
| 会话切换 | A 翻译未返回时切到 B，B 不显示 A 的语言/译文，不发送 A 的内容；切回 A 重新验证 |
| 编辑器重建 | 同客户重建后语言保留，草稿重新读取；更换客户后不延用旧语言 |
| Enter 等待 | 先按 Enter 再输入、切会话、暂停或退出登录均取消旧发送；输入法不误发 |
| 订单 | 芯片直开、选中文字预填、Esc 关闭、换会话关闭；单独确认页面登录与业务权限 |
| 退出与回退 | 托盘退出后释放页面租约，另一个宿主可以接入；无多余助手进程 |
| UI | 窄窗/低窗、125%/150% DPI、语言弹层边界及长译文滚动正常 |

普通翻译与替换验收不需要发送客户消息。Enter 真实发送只能在明确的测试会话里进行，验证客人实际收到译文；其余情况停在替换后读回即可。

排障时先确定失败在哪一层：

1. **没有助手进程**：外部宿主检查完整包目录、Node/.NET 文件和日志，不能只移动 EXE；资源注入版检查安装收据、ASAR 入口、助手载荷及启动日志，不能以是否出现托盘作为运行成功的唯一标准。
2. **客户端未连接**：现有外部宿主完全退出客户端后通过助手入口启动；资源注入版核对 bootstrap 是否执行、是否在正确阶段建立本机连接。两者都必须核对端口属于目标进程，而非其他程序。
3. **版本或页面校验失败**：记录错误码和客户端版本，对照兼容清单。厂商更新可能同时改变页面路径、文件名和指纹。
4. **有面板、无翻译**：先看认证状态，再看当前会话、客户语言、暂停状态、草稿可读性和 20,000 字符限制。
5. **订单能开、翻译需登录**：分别处理两条登录链路，不以 iframe 登录推断翻译已认证。
6. **草稿已替换但没发出**：核对是否替换模式、发送按钮是否唯一可用；人工确认草稿后发送，不循环自动点击。
7. **DOM 正常但窗口白屏**：保留实际窗口截图，按第 12.3 节继续诊断，不能因页面内部有内容就算通过。

日志应只保留错误码、阶段、耗时、脱敏位置等必要诊断。不要记录 token、密码、完整客户消息、订单详情或浏览器存储内容。构建与校验输出失败时先保存错误证据，再清理。

## 14. 构建清理、恢复与后续一次安装目标

### 14.1 清理边界

完成校验、归档必要证据并确认没有构建进程后，可删除仓库中的 `release/`、`dist/`、`dist-*`、`host/dist/`、各平台生成的 `bin/` / `obj/`、明确的构建暂存目录和不再需要的调试日志。依赖目录中的 `.vite` / `.vite-temp` 等构建缓存可重建；无需为删除缓存而删除源码、锁文件或测试。

`npm run clean:mac` 已扩展为显式构建清理：包含 `release`、`dist`、各已知 `dist-*`（含 lightweight）、`host/dist`、macOS 原生输出，以及 Windows / resident / browser-bridge 的 `bin/obj`、三种 Node 构建缓存和 `work/patch-tests`；也会递归删除工作区 PKG。仍不盲目删除整个 `work` 或依赖目录。

**不要直接删除整个 `work/`。** 其中可能有官方 DMG、原版恢复备份、安装回滚材料、截图和 JSON 验收记录；应按目录用途判断。构建结束后删除产物不影响已安装在 `/Applications` 的程序，但下一次安装、校验或分发必须重新构建，旧文档里的产物链接也可能已经失效。

Windows 显式清理示例（仓库根目录）：

```powershell
$generated = @('release','dist','dist-electron','dist-lightweight','dist-runtime','dist-embedded','host\dist','native\resident\bin','native\resident\obj','native\windows\bin','native\windows\obj','native\browser-bridge\bin','native\browser-bridge\obj')
$generated | ForEach-Object { if (Test-Path -LiteralPath $_) { Remove-Item -LiteralPath $_ -Recurse -Force } }
```

日志逐项确认后再删。用户的长期登录文件、厂商用户配置和安装备份不属于构建产物；不要把 `%LOCALAPPDATA%` 整个应用目录当缓存删除。保留一个可用回退包的副本时放到仓库构建目录之外；若本次要求连全部发行产物都删除，则回退时须从已提交源码重建，不能继续承诺仓库里有可运行旧包。

### 14.2 Windows 资源注入安装器的实施与验收要求

**本节是已确定的实现方向，尚不是现成安装命令。** 最终交付一个安装 EXE，修改官方 Electron 资源并部署助手；用户之后只打开官方客户端。现有托盘宿主不作为最终日常启动要求。

实施范围：

- **定位与兼容清单**：发现真实安装目录，核对官方 EXE、ASAR、原入口和页面资源；拒绝未知版本、已被其他补丁修改的资源和运行中覆盖。同时检查官方更新器、ASAR 完整性与签名机制，确认修改后的官方启动方式仍能运行，不通过绕过核验来适配。
- **完整载荷与入口**：打包所选宿主和其全部运行资源；追加 Windows bootstrap，记录并继续加载官方原入口，保留原业务逻辑。确认普通官方 EXE、桌面快捷方式、官方自重启都进入接入链路，而非要求用户改点另一个启动器。
- **权限与事务安装**：仅安装操作按需提权，日常客户端与助手按普通用户运行。使用安装锁、同卷暂存、校验、备份、替换和持久事务记录；复制、替换、复验失败或安装中断后可恢复。保留原 ASAR、相关资源及准确收据，不能先删除唯一原件再复制。
- **指纹与运行核验**：原版备份指纹和注入后运行指纹分开记录。安装修改了 ASAR 后，助手的兼容清单也必须对应新归档，避免拿原版哈希核验注入版；页面热更新仍单独核验。
- **进程与登录**：按 PID、启动时间和用户核验归属，确保单实例、退出清理与自重启交接。助手使用当前用户的登录存储，不因安装提权切到管理员配置；不额外要求开机自启或手动常驻托盘才能工作。
- **升级与卸载**：重复安装不得叠加 bootstrap；区分助手升级、官方版本更新和未知文件漂移。官方更新后重新评估兼容性再注入；卸载只还原与收据相符的文件，保留客户数据及原官方用户配置，不能用旧版本备份覆盖新官方程序。

安装验收必须单独覆盖：

| 场景 | 通过标准 |
| --- | --- |
| 首次安装 | 单 EXE 完成资源接入，备份与收据可核验，安装后不依赖源码目录 |
| 正常使用 | 直接双击官方 EXE 或原快捷方式，助手自动运行且面板可用，无需先打开助手 |
| 退出与重启 | 正式退出客户端后对应助手停止；官方自重启后重新接入，无孤儿或重复进程 |
| 普通用户与提权 | 受保护目录按需提权安装；日常运行与登录数据归当前用户 |
| 重复安装与助手升级 | 不重复修改入口，不丢失可恢复备份，不改写客户数据 |
| 失败与中断 | 复制失败、文件占用、校验失败、交换中断后原客户端可恢复运行 |
