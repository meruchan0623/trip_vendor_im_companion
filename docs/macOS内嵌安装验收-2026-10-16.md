# macOS 内嵌安装与分发记录

## 交付行为

主程序安装在 `/Applications/旅游商家桌面版.app`，打开它会自动启动包内助手。助手位于 `Contents/Resources/companion/旅游商家助手.app`，不依赖开发目录或用户安装 Node.js。主程序退出后，助手通过 PID 和进程启动时间确认原进程结束并退出。

启动器使用随机本机调试端口；显式指定的合法端口会保留。监听限制为 `127.0.0.1`，助手核验监听进程、主程序代码、ASAR 和页面资源后连接。厂商默认/自身 `app.relaunch()` 经新增 bootstrap 回到启动器；重启时清除旧调试参数。原厂主入口文件没有改写。

正常打开、完整退出和再次打开由本机进程日志验证。冷启动时聊天编辑器尚未出现，插件保持等待，编辑器出现后挂载；厂商重绘可恢复，而插件宿主被单独移除、同 ID 冒充或重复 ID 仍撤销租约。

## Intel 提示的原因与迁移

原包 `package.json` 的 `config.arch` 为 `arm64`，但实际主 executable、Electron Framework 和原生扩展为 Intel。厂商配置的 Apple 下载渠道同版本 DMG 也包含相同 Intel 包，ASAR SHA256 为 `e6e1a4547e3609ac858d8d71f69a982a46d6f04a8a7f4197bf4ba63ed39abb24`。

本次保持 Electron 27.3.11 与业务版本 1.2.12 / ares 1.2.15，替换主程序和 Helper 为官方 ARM64 运行时，重建/补入同版本 ARM 原生依赖。SQLite、heapdump、sharp、截图、nice、snappy 共 7 类核心依赖通过实际加载及 SQL、图像编码、压缩等冒烟。原厂入口在独立 profile 中完成初始化并加载登录页面。当前截图服务加载 ARM `node-screenshots`，并保留原厂 `desktopCapturer` 回退。

保留 6 种厂商 Intel 私有/旧工具：两个 vampire cache prebuild、vampire locker、DalDecrypt、7za、captureTool。当前启动没有触发这些私有依赖；源码未引用旧 captureTool。两个 cache prebuild 在原 Intel Electron 中也因 ABI 不一致不能加载。不能由本次结果推断所有潜在厂商路径或 macOS 28 已完整验证。

新 profile 的原厂 OCR 模型下载出现上游 404，未阻止主程序启动；本次没有修改厂商下载服务。

## 构建

Apple Silicon 开发机需 Node.js、Xcode Command Line Tools。

```bash
node scripts/lib/arm64-build-native.mjs work/mac-arm64/native-rebuild
```

从 Electron 官方 GitHub release 获取 `electron-v27.3.11-darwin-arm64.zip`；准备脚本强制校验 SHA256 `a687b199fcb9890f43af90ac8a4d19dc7b15522394de89e42abd5f5c6b735804`。

```bash
npm run prepare:mac:arm64 -- \
  --out work/mac-arm64/rebuilt \
  --runtime '<Electron ARM64 zip>' \
  --native-root work/mac-arm64/native-rebuild/node_modules
npm run package:mac:integrated -- \
  --prepared-app 'work/mac-arm64/rebuilt/旅游商家桌面版.app'
```

准备脚本保留外置 `app.asar.unpacked` 中未列入 ASAR header 的数据库迁移、ONNX 等资源。检查报告记录残余 Intel 工具并保守返回退出码 2，必须阅读报告，不能当作“全 ARM 通过”。

打包器构建助手、生成签名无关的主程序代码指纹、将完整助手和启动器嵌入主包、签名核验，再输出 ZIP 和 SHA256。ASAR 使用原始字节 SHA256；主程序代码指纹只归一化签名相关字段，代码与数据仍参与哈希，避免外层签名与内嵌助手指纹形成循环。真实重新签名后的指纹一致性已验证。

## 安装与恢复

同事只需退出旧程序，将分发包中的 app 放入 `/Applications` 并保留名称，之后直接打开主程序。不支持从下载目录、改名目录或 `~/Applications` 使用助手。账号和系统权限由各位用户自行登录/授权，分发包不携带本机登录状态。

本机原始包备份及事务：

```text
/Applications/.trip_vendor_im_companion-backups/37d19131-db82-453d-ad0e-bdf4909df198.app
/Applications/.trip_vendor_im_companion-backups/37d19131-db82-453d-ad0e-bdf4909df198.json
```

恢复前退出主程序：

```bash
npm run rollback:mac -- --transaction '/Applications/.trip_vendor_im_companion-backups/37d19131-db82-453d-ad0e-bdf4909df198.json'
```

完整备份恢复流程已实际执行成功。重复安装会验证内容；漂移时拒绝覆盖。厂商整包更新可能覆盖插件，需要重新核验新版本后安装。

本机没有 Developer ID 证书，产物采用 ad-hoc 签名，没有 Apple 公证。首次分发可能需要在系统设置的“隐私与安全性”中核对应用并选择“仍要打开”，见 [Apple 说明](https://support.apple.com/102445)。
